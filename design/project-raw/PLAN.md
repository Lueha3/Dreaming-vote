# [Project: RAW] 기획안 & 개발 계획

> **"완벽하지 않기에 더 아름다운 음악"**
> 아이폰 기본 앱 개러지밴드(GarageBand)로만 만든 음악을 공유하는, '방구석 아티스트'들의 플랫폼.
> BlueHumanity 세계관의 Phase 2 — **[BlueHumanity: CREATOR]**.

---

## 1. 한 줄 정의

**"아이폰 하나로만 만든 음악"이라는 제약(Constraint)을 인증(Authenticity)으로 바꾸는, AI 시대의 인간 창작 커뮤니티.**

- Suno/Udio가 0.1초 만에 '완벽한' 곡을 뽑아내는 시대에, RAW는 정반대에 선다.
- 서툰 박자, 기본 악기, 미완성의 흔적 — 그 자체가 콘텐츠이자 상품.
- 제약이 곧 규칙이고, 규칙이 곧 정체성이다.

## 2. 문제와 기회

| 구분 | 내용 |
|---|---|
| 문제 1 | AI 음악의 범람 → 리스너의 '진정성 피로'. 매끈한 음악은 무한 공급, 사람 냄새 나는 음악은 희소해짐 |
| 문제 2 | 방구석 뮤지션은 만들 곳(개러지밴드)은 있는데 **보여줄 곳**이 없음. 사운드클라우드/유튜브에선 프로 결과물과 같은 링에서 비교당함 |
| 기회 1 | "폰으로만 만들었다"는 조건이 **공정한 출발선**을 만들어줌 (장비 격차 제거) |
| 기회 2 | 애플 생태계와의 궁합 — "아이폰만으로 창작하는 생태계"는 애플이 가장 사랑하는 서사 |

## 3. 타겟

- **창작자**: 비싼 장비는 없지만 영감은 넘치는 10~20대 방구석 뮤지션. 개러지밴드를 깔아만 두고 뭘 해야 할지 모르는 잠재 창작자 포함.
- **리스너**: 가공된 K-POP·AI 음악에 피로감을 느끼고, 누군가의 일기장 같은 투박한 음악을 원하는 사람.
- **(BlueHumanity 연계)**: 아이와 함께 첫 곡을 만들어보고 싶은 부모.

## 4. 핵심 원칙 — "제약이 곧 인증이다"

1. **오직 개러지밴드**: iPhone/iPad GarageBand로 만든 곡만 등록 가능.
2. **불완전함의 보호**: '못했다'가 아니라 '진짜다'. 조롱성 댓글 제재, 응원 중심 커뮤니티 톤 강제.
3. **증명은 놀이로**: 검증 절차 자체를 챌린지·배지·콘텐츠로 승화.

## 5. 3+1단계 검증 시스템 (Trust Engine)

| 단계 | 이름 | 방식 | 비고 |
|---|---|---|---|
| 1 | `.band` 소스 업로드 | 음원과 함께 개러지밴드 프로젝트 파일(.band)을 업로드. 서버에서 패키지 내부 plist를 파싱해 외부 AU/플러그인·임포트 오디오 비중을 검사 | 물리적 증거. 파일 공개 시 학습 자료로 재활용 (→ BM Option B) |
| 2 | Proof of Work 영상 | 전체 트랙을 스크롤 재생하는 15~30초 화면 녹화 필수 첨부 | 감성적 신뢰 + 틱톡/릴스 홍보 소재로 이중 활용 |
| 3 | 피어 리뷰 | 개러지밴드 고수 유저의 신고·검수. 적중 시 포인트/명예 배지("잡았다 요놈") | 커뮤니티 자정 + 고인물 리텐션 장치 |
| +1 | 사운드 핑거프린팅 | 개러지밴드 기본 루프/악기 파형 DB 대조, 외부 샘플 비중 높으면 자동 '검토 대상' 분류 | Phase 3 이후 (수익 발생 후 투자) |

**검증 레벨 배지**: `RAW Verified` (1+2 통과) / `RAW Certified` (피어 리뷰까지 통과) — 프로필과 곡에 노출.

## 6. 핵심 기능 (MVP 범위)

1. **피드**: 최신순/챌린지별. 알고리즘 최소화 — "라디오 RAW" 모드(무작위 재생)로 롱테일 노출 보장.
2. **곡 업로드**: 음원(m4a/mp3) + `.band` 파일 + Proof 영상 + 커버(자동 생성, 아래 7-9 참조).
3. **곡 상세**: 파형 플레이어, 사용 악기 태그, 검증 배지, 응원 반응(❤️ 대신 "박수"·"소름"·"눈물" 등 감정 반응).
4. **프로필**: 첫 곡부터 최신곡까지 '성장 타임라인' 뷰.
5. **주간 챌린지**: "이번 주 주제: 808 Bass + Grand Piano만" 식의 제약 챌린지. 참여곡 모아보기 + 투표.
6. **신고/피어 리뷰**: 검증 시스템 3단계 구현.

## 7. 추가 제안 기능 (Claude 제안)

1. **리믹스 포크(Remix Fork)**: 공개된 `.band` 파일을 '포크'해서 이어 만들기. 곡마다 포크 트리(계보)가 시각화됨 — GitHub의 음악 버전. 원작자에게 크레딧·포인트 자동 배분.
2. **듀엣/합주 레이어**: 남의 곡 위에 내 트랙 하나만 얹어 답가하는 기능. "이 베이스에 드럼 얹어줄 사람?"
3. **데일리 루프 스트릭**: 하루 15초 루프 1개 업로드 습관 시스템. 스트릭 유지 시 배지 — 창작을 '운동'처럼.
4. **파형 커버 아트 자동 생성**: 커버 이미지도 외부 툴 금지. 업로드된 음원 파형+색으로 앱이 자동 생성 → 제약의 미학을 비주얼 아이덴티티로 통일.
5. **복면 아티스트 모드**: 익명 업로드 → 반응이 쌓이면 공개 여부 선택. 창작 심리 장벽 제거.
6. **첫 곡 부트캠프**: 개러지밴드를 처음 여는 사람을 위한 7일 미션 온보딩(오늘은 Live Loops로 8마디만). 잠재 창작자를 창작자로 전환하는 깔때기.
7. **부모-자녀 콜라보 배지** (BlueHarmony 연계): 가족 계정으로 함께 만든 곡에 전용 배지. PARENTING ↔ CREATOR 간 유저 흐름 연결 고리.
8. **월간 컴필레이션 투표**: 유저 투표로 선정된 곡을 실제 음원 유통(BM Option A의 커뮤니티 참여 장치).
9. **제작 노트(라이너 노트)**: 곡마다 "이 곡을 만들 때 나는…" 짧은 일기 첨부 — '누군가의 일기장 같은 음악'이라는 포지셔닝을 텍스트로 완성.
10. **사용 악기 자동 태깅**: `.band` 파싱 시 사용된 기본 악기 목록을 자동 추출·태깅 → "Grand Piano로 만든 곡" 탐색 가능, 챌린지 검증도 자동화.

## 8. 비즈니스 모델

| 옵션 | 내용 | 시점 |
|---|---|---|
| A. 챌린지 & 컴필레이션 | 월간 경연 → 선정곡 앨범 유통(수익 배분) | Phase 2 |
| B. `.band` 프로젝트 파일 마켓 | 프로젝트 파일·모바일 작곡 노하우 유료 판매 (수수료 15~20%) | Phase 3 |
| C. 브랜드 협업 | "아이폰만으로 창작하는 생태계" — Apple 등 브랜드 챌린지 스폰서십 | 규모 확보 후 |
| D. RAW+ 구독 (제안) | 업로드 용량 확장, 포크 무제한, 컴필레이션 우선 심사 등 소프트 구독 | Phase 3 |

## 9. 리스크 & 정책

- **상표**: "GarageBand"는 Apple 상표. 서비스명·마케팅에서 비공식 팬/커뮤니티 플랫폼임을 명시하고, 앱 이름에는 미사용 (Project RAW).
- **저작권**: 개러지밴드 기본 루프·사운드는 Apple 라이선스상 창작물 상업 이용 허용 — 단, 유통(BM A) 시 약관 재검토 필요.
- **`.band` 파일 프라이버시**: 프로젝트 파일 공개는 선택제(비공개 검증만 vs 공개+포크 허용).
- **커뮤니티 톤**: '불완전함 조롱'은 최우선 제재 대상. 신고 카테고리에 별도 항목.

## 10. 개발 계획

### 스택 (Dreaming-vote에서 검증된 스택 재사용)

- **프론트**: Next.js (App Router) + Tailwind, 반응형 모바일 웹 → PWA (홈 화면 추가, iOS 공유 시트 업로드 대응)
- **백엔드**: Next.js API Routes + Prisma
- **인프라**: Supabase (Auth — **Apple 로그인 필수**, Postgres, Storage — 음원/.band/영상), Vercel 배포
- **오디오**: 웹 파형 렌더링(wavesurfer.js 또는 자체 Canvas), 서버 사이드 파형 데이터 사전 추출
- **`.band` 검사기**: 업로드 시 zip 해제 → `projectData`/plist 파싱 → 외부 플러그인·임포트 검출 (Edge Function)

|---|---|---|---|
| **0. 컨셉 검증** | 2주 | 이 랜딩 페이지 + 사전등록(웨이트리스트), 틱톡/릴스 바이럴 3편 ("아이폰으로만 만든 노래") | 사전등록 300명 |

### KPI

- 북극성 지표: **주간 신규 업로드 곡 수** (트래픽이 아니라 창작 행위가 지표)
- 보조: 업로드 완주율(작성 시작→검증 통과), 챌린지 참여율, 포크 발생 수, D7 리텐션

## 11. BlueHumanity 세계관 내 위치

```
Phase 1  [PARENTING]  INSIGHT16 · PARAN AI   "부모가 먼저 바로 서야 한다"
Phase 2  [CREATOR]    Project RAW            "AI의 완벽함 대신, 불완전한 진정성을 노래하라"
Phase 3  [ESSENCE]    철학·인문학 살롱          "생산성을 넘어, 인간다움의 본질로"
```

- 부모와 아이가 아이폰 하나로 함께 곡을 만들어 올리는 흐름 = PARENTING과 CREATOR를 잇는 다리.
- 아이의 '창의적 자아실현' 기록이 쌓이는 곳 — 단순 취미 플랫폼이 아니라 세계관의 자아실현 파트.
