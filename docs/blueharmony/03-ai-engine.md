# 03. AI·데이터 설계 — 코치, 거울, 그리고 PARAN AI로 가는 길

## 1. 데이터 모델 (핵심 엔티티)

```
Parent (User)                Child                     FamilyPairing
├ 양육 성향 프로필            ├ 출생연도, 호칭            ├ parentId × childId
├ 피양육 경험 태그            ├ 기질 프로필(차원 점수)     ├ 조합 아키타입
└ 부부 연결(PartnerLink)     └ (실명·사진 없음)          └ 충돌 지도 캐시

InteractionLog (핵심 자산 — 매일 쌓이는 종단 데이터)
├ 상황 태그(프리셋 12 + 자유) ├ 부모 발화 요약 ├ 감정 온도 ├ 결과 피드백(먹힘/안먹힘)
├ 사용한 코치 스크립트 id     └ timestamp

CoachSession                  WeeklyMirror              TrajectorySim
├ 입력(상황·맥락)             ├ 주간 패턴 집계            ├ 입력: 4주+ 로그
├ 생성 스크립트(3단 포맷)     ├ 대응 유형 분포            ├ 궤적 A/B 서사
└ 사후 피드백                 └ 다음 주 미션              └ 근거 지표 스냅샷
```

설계 원칙: **아이는 엔티티로 최소화**(연도+기질 점수만), **로그는 부모의 1인칭 기록**.
"성인의 행동 패턴 ← 유년기 환경" 연관성 연구(일기의 원점)는 이 종단 로그가 수년 쌓여야
가능해진다. 즉 InteractionLog 스키마의 품질 = 회사의 장기 가치.

## 2. 기질·성향 모델 — 근거 위에 세운다

| 모듈 | 이론적 기반 | 구현 |
|---|---|---|
| 아이 기질 | Thomas & Chess 9차원 → 현대적 축약(활동성·규칙성·적응성·반응강도·민감도·지속성 등), Rothbart 기질 모델 | 부모 관찰 응답 기반 간이 검사 (5분, 상황 문항 위주) |
| 부모 양육 성향 | Baumrind 양육 유형(권위형/권위주의형/허용형/방임형) × Gottman 정서 코칭 메타감정 유형(축소전환형/억압형/방임형/감정코칭형) | 자가 보고 검사 + 대물림 문항(본인의 피양육 경험) |
| 조합 아키타입 | 위 두 축의 교차 — 이름은 마케팅 언어(예: "화산×유리병"), 내부 데이터는 차원 점수 유지 | 아키타입은 표시용, 로직은 항상 원점수 사용 |
| 개입 원리 | 감정코칭 5단계, 행동주의(선택지 제시·자연적 결과), 애착 이론, 비폭력대화(NVC) | 스크립트 생성 프롬프트의 근거 태그 체계 |

**정직성 원칙**: 초기 간이 검사는 심리측정학적으로 타당화된 도구가 아니다.
- 화면에는 "참고용 프로파일"임을 명시하고, 국내 공인 검사(JTCI 등)와 경쟁하는 척 하지 않는다.
- 자문단(04-roadmap §5) 합류 후 문항 타당화 연구를 공동 진행 → "전문가 검증 검사"로
  업그레이드하는 것 자체를 마일스톤이자 보도자료로 만든다.
- 이 겸손함이 역설적으로 전문가 영입의 미끼가 된다 — "당신의 이론을 표준으로 만들
  데이터와 유통 채널이 여기 있다"는 제안이 가능해지기 때문.

## 3. SOS 코치 파이프라인

```
입력(프리셋/채팅) 
  → 컨텍스트 조립: 아이 기질 점수 + 부모 성향 + 아이 나이 + 최근 로그 3건 + 과거 "먹힌" 스크립트
  → 안전 필터 (위기 신호 스크리닝 — §6)
  → LLM 생성 (프롬프트 콘솔의 활성 PromptVersion 사용, 스트리밍)
  → 구조 검증 (zod: 지금 이 말 / 지금은 금지 / 30초 원리 — 실패 시 ParsingLog + 폴백)
  → 폴백: LLM 실패·타임아웃 시 해당 상황×조합의 검증된 정적 스크립트 (오프라인에서도 동작)
  → 사후 피드백 수집 → 스크립트 승률 테이블 갱신
```

- **속도 예산**: 첫 토큰 2초, 첫 대사 완성 10초. 급한 순간용 제품의 SLA다.
  프리셋 12종 × 주요 조합은 사전 생성 캐시로 0초 응답, LLM은 개인화 보강에 사용.
- **프롬프트 운영**: 기존 admin/prompts 콘솔로 버전 관리·즉시 교체. 자문단 감수를
  코드 배포 없이 반영. A/B는 PromptVersion 단위로.
- **모델 전략**: 응답 지연에 민감한 코치는 경량 모델 + 캐시, 주간 리포트·궤적 서사는
  고성능 모델 배치 생성(야간). 모델 벤더는 어댑터로 추상화해 교체 가능하게 (현재
  Gemini 연동 경험 + Claude API 병행 검토).

## 4. 미래 거울 — "예측"의 정직한 구현

궤적 시뮬레이션은 3층으로 만든다. 각 층의 확실성 수준을 섞지 않는 것이 핵심.

| 층 | 내용 | 확실성 |
|---|---|---|
| ① 사실 층 | 유저 본인의 집계: 충돌 빈도 추이, 대응 유형 분포, 입금/출금 비율(긍정:부정 상호작용 비 — Gottman 5:1 연구 프레임 차용) | 높음 — 본인 데이터 |
| ② 연구 층 | "이런 패턴이 지속된 가정에서 관찰되는 경향" — 공개 종단 연구·자문단 감수 지식 기반 | 중간 — 출처 표기 |
| ③ 서사 층 | 궤적 A(현재 패턴 지속)/궤적 B(미션 수행 시)의 스토리텔링 — LLM 생성 | 시뮬레이션 — 명시 |

- UI 규칙: ③서사 층에는 항상 "이것은 예언이 아니라, 오늘 바꿀 수 있는 것을 보여주는
  시뮬레이션입니다" 프레임 고정. 확률 수치("불행 확률 n%")는 표시하지 않는다.
- 궤적은 항상 **A/B 쌍**으로 보여준다. 나쁜 궤적만 단독으로 보여주는 것은 금지
  (겁주기 → 죄책감 → 이탈. 원칙 1 위반).
- 유저가 쌓이면 ② 연구 층을 자사 코호트 통계로 점진 대체: "비슷한 조합의 가정
  1,200곳에서 이 미션 수행 후 충돌 빈도가 줄었어요" — 이것이 예측 엔진 v1이다.
  개인 미래 예언이 아니라 **코호트 기반 개입 효과 예측**으로 완성한다.

## 5. PARAN AI로 가는 데이터 전략

| 단계 | 자산 | 잠금 해제 조건 |
|---|---|---|
| D0 | 검사 프로파일 (횡단) | 런칭 즉시 |
| D1 | 상호작용 로그 + 개입 결과 (스크립트 승률) | MAU 수천 × 수개월 |
| D2 | 조합별 개입 효과 코호트 통계 (예측 엔진 v1) | D1 축적 + 자문단 검수 |
| D3 | 종단 궤적 데이터 (연 단위) — "유년기 환경 ↔ 이후 패턴" 연구 가능 | 2~3년 리텐션 |
| D4 | PARAN AI 모듈: 조합 프로파일 + 개입 정책을 API/SDK로 외부 제공 (로봇·디바이스·에듀테크) | D2 이상 + B2B 파트너 |

블록체인(데이터 주권·보상)은 D3~D4 시점에 다시 검토한다 — 그 전에는 풀 문제가 없다.

## 6. 안전·윤리·법무

### 위기 프로토콜 (1일차 탑재)
- 입력·로그에서 학대 정황, 자해·자살 위험, 심각한 발달 우려 신호를 스크리닝
  (키워드 + LLM 분류 2단). 감지 시 코칭 톤 전환 → 전문 기관 안내 카드 고정 노출:
  - 아동학대 신고 **112** / 보건복지상담센터 **129** / 자살예방 상담 **109** / 청소년 상담 **1388** / 거주지 육아종합지원센터
- 반복 감지 시 운영진 검토 큐(기존 ContentReport 흐름 확장)로 승격. 대응 매뉴얼 문서화.
- 앱 전역 고지: "블루하모니는 의료·심리 상담을 대체하지 않습니다."

### 개인정보 (민감정보 취급 설계)
- 아동 데이터 최소화: 실명·사진·정밀 생년월일 미수집(출생연도만). 아이 계정 없음.
- 육아 기록은 민감정보에 준해 취급: 목적 외 이용 금지, 서드파티 광고 SDK에 로그 미제공,
  LLM 벤더에는 학습 미사용(no-training) 조건 API만 사용, 프롬프트에 식별자 미포함.
- 유저 권리: 전체 데이터 내보내기·완전 삭제를 마이 탭에서 셀프서브로 제공.
- 연구·통계 활용은 가입 동의와 분리된 **선택 동의** + 비식별화 파이프라인. (D2~D3
  데이터 전략의 전제 조건이므로 초기부터 동의 체계를 정확히 깐다.)
- 만 14세 미만 사용자 가입 차단 (부모용 서비스임을 약관·심사 대응에 명시).

### 표현·클레임 가드레일
- 금지: 진단명 부여, 발달장애 감별, "불행 확률", 아이 개인의 미래 단정.
- 필수: 근거 태그(어떤 이론에 기반한 조언인지), 시뮬레이션 고지, 낙인 언어 필터
  (생성 결과 후처리 검사에 금칙어·톤 체크 포함).
