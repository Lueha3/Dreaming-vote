# 06. 물리 기반 실사형 시뮬레이션 — "몸으로 배우는 육아"

> 방향 확정 (2026-07): S-트랙은 웹 3D 스타일라이즈드가 아니라 **물리 엔진 기반,
> 실제적인 부모·아이의 움직임이 구현되는 스팀(Steam)급 시뮬레이션**으로 간다.
> 05-simulation.md의 아이 브레인·퀘스트 구조·No-Blame 게임 문법·보상 설계는 전부 유지되며,
> 그 위에 얹히는 **몸(body)의 층**이 이 문서다.

## 0. 이 게임의 심장 — 근긴장도(Muscle Tone) 시스템

"실제같은 아이"를 만드는 것은 피부 텍스처가 아니라 **행동의 물리**다.
실제 육아의 몸싸움은 전부 근긴장도의 문제다:

| 실제 육아 현상 | 물리적 실체 | 게임 구현 |
|---|---|---|
| 마트 드러눕기 | 아이가 온몸의 힘을 빼서 '죽은 무게'(dead weight)가 됨 — 15kg이 40kg처럼 느껴짐 | 감정 상태 → 근긴장도 0 → 액티브 래그돌이 림프(limp) 상태로 — 들어올리면 흘러내림 |
| 떼쓰며 발버둥 | 높은 긴장 + 무작위 큰 토크 | 관절 모터에 랜덤 토크 분사, 캐리 constraint에 큰 외란 |
| 유리병 기질의 '얼어붙기' | 과긴장 — 몸이 뻣뻣하게 굳음 | 관절 강성 최대, 이동 애니메이션 차단 |
| 손잡고 걷다 홱 끌기 | 부모 견인력이 아이 어깨 관절 한계 초과 | 손 constraint 장력 측정 → 임계 초과 시 감정 온도 상승 (실제로 팔꿈치 탈구 위험이 있는 행동!) |
| 진정 후 다시 일어나기 | 근긴장 회복 — 스스로 몸을 일으킴 | 래그돌 → 애니메이션 블렌드백 (Physics Control) |

**감정 엔진(05의 아이 브레인)이 근긴장도·협조도 두 파라미터를 출력하고, 물리 계층이 그것을
몸으로 번역한다.** 마음 온도가 게이지가 아니라 '안았을 때 손끝으로 느껴지는 무게와 저항'이
되는 것 — 이것이 이 게임이 세계 최초로 하는 일이다. (참조할 선행작이 없다. 육아 시뮬 장르에서
액티브 래그돌 감정 결합은 블루오션이다.)

> **P0 기술 데모 (완성)** — 이 시스템의 검증 데모가 [`s0-demo/physics-demo.html`](./s0-demo/physics-demo.html)에
> 있다 (브라우저 실행, 자체 제작 버렛(Verlet) 물리). 마트 통로에서 아이 손을 잡고 걷고,
> 젤리 매대 앞 떼쓰기 → 드러눕기(림프 래그돌) → 달래기 → 근긴장 회복 → 안아 들기까지
> 전부 물리로 동작한다. 언리얼로 가기 전에 게임플레이가 재미있는지 여기서 먼저 확인한다.

## 1. 엔진·플랫폼 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| 엔진 | **Unreal Engine 5** | Chaos 물리 + Physics Control 플러그인(액티브 래그돌·애니-물리 블렌딩 내장), Motion Matching(5.4+ PoseSearch, GASP 샘플), Control Rig/Full-Body IK, 실사급 렌더(Lumen/Nanite), 블루프린트로 1인 개발 가능. Unity 대비 '실사+물리' 목표에 정확히 부합 |
| 플랫폼 | **PC(Steam) 우선, 모바일은 후속** | 실사 물리 시뮬은 모바일 발열·성능 한계가 크다. "스팀 게임같은" 경험은 PC가 본진 — 모바일은 기존 웹 앱(나침반·코치·광장)이 담당하고, 게임의 라이트 버전 이식은 EA 이후 판단 |
| 시점 | 1인칭 기본 + 3인칭 전환 | 1인칭 = 아이 눈높이로 쪼그려 앉는 것이 실제 화면 변화가 되는 시점(훈육 기술의 물리화). 3인칭은 캐리·이동 편의 |
| 입력 | 키보드/패드 + **마이크(STT)** | 실제 목소리로 아이를 달래는 것이 이 게임의 킬러 입력 — "마이크에 대고 아이를 진정시키는 스팀 게임". Whisper 로컬 STT → LLM 브레인 판정 |

## 2. 캐릭터 기술 스택 (UE5)

### 2.1 부모(플레이어)
- 로코모션: Motion Matching (GASP 샘플 개조) — 걷기/서기/쪼그려 앉기/돌아서기
- **쪼그려 앉기 = 게임 메커닉**: 아이 눈높이에서 말하면 대화 효과 배율 상승 (실제 훈육 원리의 물리화)
- 손 뻗기·잡기: Control Rig IK 체인 — 손잡기, 어깨 짚기, 안아 올리기 각각 다른 그립 소켓
- 캐리 시스템: 힙 캐리(옆구리)·프론트 캐리(안기)·숄더 캐리(업기) 3종 — 아이 근긴장도에 따라
  같은 캐리도 안정도가 달라진다 (림프 상태 힙 캐리 = 흘러내림, 이게 플레이어가 몸으로 배우는 것)

### 2.2 아이 (핵심 기술)
- 스켈레톤: 연령별 프로포션 3종 (4세/7세/14세 — 05의 연령 밴드 유지)
- 로코모션: **아동 모캡은 쓰지 않는다** (아동 배우 모캡의 윤리·법 리스크). 성인 모캡
  리타게팅 + 프로시저럴 보정(짧은 보폭, 높은 케이던스, 불안정성 노이즈, 4세는 와이드 스탠스)
- **Physics Control 기반 액티브 래그돌**: 항상 물리 시뮬레이션 위에 있고, 근긴장도 파라미터가
  애니메이션 추종 강도(strength/damping)를 실시간 제어
  - tone 1.0 = 애니메이션 그대로 (걷기, 손잡기 협조)
  - tone 0.6 = 뻣뻣함 (유리병 얼어붙기 — 끌면 통나무처럼 기울어짐)
  - tone 0.3 + 랜덤 토크 = 발버둥 (불꽃놀이 폭발)
  - tone 0.0 = 완전 림프 (드러눕기 — 순수 래그돌, 죽은 무게)
- 감정→표정: 메타휴먼 페이셜 대신 스타일라이즈드 블렌드셰이프 (아래 §3)
- 시선(gaze) 시스템: 아이가 부모를 보는지/피하는지가 감정 상태의 제1 신호 — 철회 상태에선
  눈을 안 맞춘다. 플레이어가 '읽어야 할' 비언어 신호의 3D 구현 (05 §2.4 계승)

### 2.3 감정 엔진 통합
```
아이 브레인 (05 설계 그대로)                    몸 계층 (이 문서)
StateTree: 기질 벡터 × 상태 게이지    ──▶   근긴장도 (0..1)
  반응 모드: 협조/협상/얼어붙기/폭발/림프 ──▶   협조도 (이동 목표 추종률)
LLM 대사 생성 (클라우드 + 오프라인 대사뱅크) ─▶  표정·시선·음성(TTS)
플레이어 마이크 발화 → Whisper STT ──▶   판정기(개입 태그 분류) → 게이지 델타
```
- 물리 이벤트가 역방향으로도 흐른다: 세게 끌기·급하게 들기·넘어뜨림 → 온도 상승.
  **말과 몸이 같은 감정 시스템에 연결된 최초의 육아 시뮬.**

## 3. 아트 방향 — "실사는 모션에, 스타일은 얼굴에"

실사(포토리얼) 아동 캐릭터는 두 가지 벽이 있다: ①불쾌한 골짜기(메타휴먼 아동은 최상급
스튜디오도 실패하는 영역) ②실사 아동으로 갈등·훈육 장면을 연출하는 것의 윤리·심의 리스크.

**권고: 실사풍 스타일라이즈드** — 라스트 오브 어스·라이프 이즈 스트레인지 계열의 결.
프로포션·모션·물리는 완전히 사실적으로, 표면(피부·눈)은 한 겹 스타일라이즈. "실제같다"는
감각의 80%는 모션과 무게감에서 오고, 그 둘은 §0~2가 담당한다. (최종 아트 방향은 P2 버티컬
슬라이스에서 캐릭터 컨셉 2안 비교 후 확정 — 창업자 결정 사항.)

## 4. 콘텐츠 구조 — 시나리오에서 하루 루프로

| 단계 | 콘텐츠 | 비고 |
|---|---|---|
| EA 초기 | **시나리오 모드**: S0 퀘스트 3종의 완전한 3D화 — 마트(4세)·거실 미디어 전쟁(7세)·닫힌 방문(14세) | 검증된 대화 그래프 재사용, 물리 레이어만 추가 |
| EA 중기 | **하루 루프**: 아침 준비 → 등원 → 저녁 → 잠자리, 창발적 갈등 | 진짜 시뮬레이션 게임화 |
| 정식 | **우리 아이 임포트**: 웹 앱 계정 연동 — 나침반 기질 프로필을 게임 속 아이에게 이식 | 웹↔게임 퍼널의 완성, "우리 아이의 사춘기 미리보기"를 3D로 |
| 확장 | 부부 협동 멀티(한 명은 부모, 한 명은 관찰 코치) | 05 S2 계승 |

Steam 포지셔닝: 진지한 육아 시뮬레이터는 현재 공백 장르다 (기존작들은 전부 패러디·조롱 톤).
'PowerWash Simulator'가 청소를 힐링으로 만들었듯, 육아의 어려움을 이해와 숙련으로 바꾸는
**진심 시뮬레이터** 포지션. 스트리머 재생성(마이크로 아이 달래기 장면)이 마케팅 엔진.

## 5. 개발 계획 — 게이트식 4단계

| 단계 | 기간 | 내용 | 게이트 |
|---|---|---|---|
| **P0 웹 물리 데모** | 완료 | 근긴장도 시스템 검증 (`s0-demo/physics-demo.html`) — 손잡기·끌기 장력·드러눕기·달래기·캐리 슬립 전부 동작 | 메커니즘이 '이해되고 재미있는가' 플레이 피드백 |
| **P1 UE5 그레이박스** | 2~3개월 | 맨네킹 2체(부모+4세), Physics Control 근긴장 시스템, 손잡기/캐리/림프, 마트 통로 1개, 마이크 STT 1종 | 림프 캐리가 '느껴지는가' — 패드 진동+무게 중심 이동으로 죽은 무게가 체감되면 통과 |
| **P2 버티컬 슬라이스** | +6개월 | 마트 시나리오 완성형(아트·사운드·표정), 감정 엔진 풀 통합, Steam 페이지 오픈 | 위시리스트 목표치 + 플레이테스트 NPS |
| **P3 얼리 액세스** | +12개월 | 시나리오 3종 + 하루 루프 초기, 웹 계정 연동 | EA 판매·리뷰 |

**1인 개발 현실** (정직하게, 한 번만):
- P1까지는 1인+AI 가능: 블루프린트 + GASP/Physics Control 샘플 + 마켓플레이스 에셋. 코딩보다
  물리 튜닝이 본체 — P0 데모에서 파라미터 감각을 미리 잡은 이유.
- P2부터는 캐릭터 아티스트·테크니컬 애니메이터 외주/합류가 필수. 웹 앱 Phase 1(수익 검증)과
  동시 진행은 불가능한 볼륨 — **웹 앱이 Phase 1 게이트를 통과해 캐시카우가 된 뒤 P2 착수**가
  기본 시퀀스다 (또는 P1 그레이박스 영상으로 게임 전문 투자·정부 게임 지원사업을 먼저 잡는 경로).
- 절차: Steamworks 등록($100), 게임물 자체등급분류(스팀은 IARC), 확률형 아이템 없음 유지.

## 6. 기존 자산과의 관계

- **웹 앱 (나침반·코치·광장·거울)** = 모바일 본진이자 데이터·브레인 플랫폼. 그대로 전진.
- **S0 대화 데모** = 아이 브레인 검증기. 대화 그래프·판정 루브릭이 게임에 직수입된다.
- **P0 물리 데모** = 몸 계층 검증기. 여기서 잡은 파라미터 곡선(온도→긴장도 매핑, 장력 임계값,
  슬립 축적률)이 UE5 Physics Control 튜닝의 시작값이 된다.
- 웹 앱 유저 → 스팀 위시리스트 퍼널, 스팀 유저 → 웹 앱 구독 퍼널. 서로가 서로의 마케팅.
